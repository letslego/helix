What Helix does

You describe an agent with conventional paths. Helix loads those files, runs a durable loop, and keeps an event timeline you can replay.

Filesystem-first

Paths define capabilities. Tool names come from filenames. Skills are Markdown. No hidden registry.

Local-first durability

Sessions, checkpoints, and memory live under .helix/. Crash the process; resume from disk.

Provider-agnostic

Mock provider for demos, OpenAI-compatible endpoints for production, and model fallback chains.

Cost & policy aware

Token/cost estimates, approval gates, and deny lists keep agents operable by humans.

Operator console

A built-in web console streams conversation turns beside the durable event timeline.

Replay debugging

helix replay <session> prints every model call, tool result, and approval pause.

Live demo walkthrough

A two-minute tour of scaffolding an agent, running the travel example, and reading the durable timeline.

  1. Author — instructions, tools, skills, and policies as files.
  2. Run — Helix loads the directory and executes a durable turn.
  3. Operate — inspect cost, approvals, memory, and replay the session.

Quick start

npx @letslego/helix init my-agent
cd my-agent
npm install
npx helix console

Open the console, ask for weather or a trip plan, and watch tools + checkpoints appear in the timeline.

Minimal tool

import { defineTool, z } from "@letslego/helix/tools";

export default defineTool({
  description: "Mock weather",
  inputSchema: z.object({ city: z.string() }),
  async execute({ city }) {
    return { city, condition: "Sunny", temperatureF: 72 };
  },
});

Why teams pick Helix

  • Works offline with the mock provider
  • No cloud lock-in for durability
  • Human approvals before side effects
  • Memory vault for preferences across sessions
  • Apache-2.0, built for inspection
